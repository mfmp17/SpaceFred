date: 2026-11-25
summary: Windows come back to the right workspaces after a restart, an unplugged display no longer strands them, and Fullscreen Layout stays put while you open another window.
---
## Major
- Spaceman remembers where each window was, per app, so a multi-window app returns its windows to the workspaces they were on after a restart, and a window reopened on a hidden workspace comes back at its remembered frame. The match uses the window's title and its `AXDocument` path, kept only in the local mode-`0600` `window-memory.json`: titles never enter `workspace-state.json`, `parked-windows.json`, snapshots, logs, `ctl debug`, `doctor` or the HUD.
- New setting, `[settings] pause_on_builtin_display` in Settings › General: Spaceman pauses and restores every window when the last external display is unplugged, and resumes tiling when one reconnects. While paused the menu bar icon dims and says so, and a status toast reports the change without taking focus.
- Fullscreen Layout is sticky: opening, routing, moving or unfloating another window stays in Fullscreen Layout and shows the Workspace HUD instead of splitting the workspace back up. macOS Open and Save panels always float, in every layout.
- Display unplug and parking recovery are harder to strand: a window left completely off screen by an unplug is brought back onto a remaining display, a restore that lands off-centre is clamped onto one, and a recovery record is no longer dropped because one display snapshot happened to omit the window.

## Improvements
- A native tab keeps its tile's slot in any app, not just Ghostty, including under a route-every-window rule and when the tab's app caps it below the tile's frame.
- Trackpad workspace swipes follow the macOS Natural scrolling setting, as Spaces does. A three- or four-finger Space swipe now holds layout until macOS reports the desktop change, and a stationary touch no longer holds it up.
- New Labs: Focus follows mouse (`focus_follows_mouse`), a compact or hidden menu bar icon (`menu_bar_icon_style`), routing every window of an app (`route_all_windows`), and capping a lone window's height as well as its width (`single_window_height`).
- `pin` is accepted directly in `[shortcuts.bindings]`, and every config edit — from `⌥⇧Tab`, the CLI and Settings — keeps the comments and headings already in `config.toml`, including when a key returns to its default.

## Fixes
- A display that two assignments name keeps showing the same workspace across a restart, an unplug and reconnect, and after a selector edit that goes back to the display it showed; a workspace moved while its display was hidden no longer takes the shown one with it, and a dragged pin steps the display it is on.
- A second `move-tab` before the first lands no longer discards the tab's destination, and a window minimized by hand stays minimized when you leave its workspace and come back.
- Leaving native fullscreen in a browser re-parks that app's windows instead of re-homing them, and an always-on-top window at a parking spot is left alone.
- A held drag that previews a swap keeps it when you release, after a numbered move and after a layout toggle made mid-drag; releasing where a swap was previewed uses the layout that is current then.
- Windows that cannot be moved are retried with a backoff rather than every cycle, and a layer-3 overlay the window server lists is filtered out instead of being mistaken for a window to place.
- Settings › Shortcuts shows which shortcuts still run, row by row, when a saved table is rejected.
